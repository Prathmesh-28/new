## Frontier Lab (`/frontier`) — 11 tools

Headroom's R&D sandbox previewing the next decade of SMB finance (real-time, ambient, autonomous, quantum-safe) — shipping the buildable bits as working tools and the rail-dependent bits as honest interactive mockups. Stakeholders: owner. Backend: NONE — experimental/preview; durable tools persist only via `useFeatureState` (per-account KV sync), preview/derived tools compute client-side. A persistent honest banner warns that `Preview`-badged tools are interactive mockups, not live money rails.

Tabs (`TABS` array, line 23–35) carry a `"today" | "preview"` flag; `Overview` cards (line 99–110) carry a `live` boolean. Both classifications below match the source.

- **Overview** — no inputs (reads `store` → `computeFinancialSnapshot`) → renders a "what this lab is for" blurb, 4 live KPI cards (cash on hand + account count, monthly net w/ cash-generative/burning sub, runway in days or ∞, debt outstanding + loan count) and a grid of 10 launcher cards (one per other tool, each tagged LiveBadge or PreviewBadge, click → `onOpen(tab)`) → navigation hub. _Persist: none._ _Class: Indicative._ **Interactive** (live snapshot + navigation; no own output).

- **Alert Triggers** (`AlertTriggers`, line 180) — inputs: rule name, event (`low_balance` / `large_expense` / `invoice_overdue` / `new_revenue` / `debt_due`), threshold (₹ for money events, else days — label switches via `isMoneyEvent`), channel (`in_app` / `whatsapp` / `email`) → CRUD over event→notification rules: add (validates name + numeric threshold), toggle Active/Paused, delete; renders rules table → durable trigger rules. Note: WhatsApp/email delivery activates "as those channels are connected"; rules "evaluated by the Ambient Rules engine." _Persist: `frnt-alert-rules` (useFeatureState KV)._ _Class: KV._ **Interactive.**

- **Ambient Rules** (`AmbientRules`, line 289) — inputs: metric (`cash` / `runway` / `monthly_net` / `debt_outstanding`), operator (`<` / `>`), threshold value, action text → arms background "if metric op value then action" rules and evaluates them **live** against the real `computeFinancialSnapshot`; shows 4 current-metric cards, a "N rule(s) firing right now" orange panel, and a rules table with per-row Firing/Quiet state + current value + delete → live-evaluated automation rules. _Persist: `frnt-ambient-rules` (useFeatureState KV)._ _Class: KV (rules) + Indicative (live evaluation against real data)._ **Interactive.**

- **Scenario Supercompute** (`ScenarioSupercompute`, line 412) — inputs: starting cash (prefilled from live `snap.cash`), monthly revenue, revenue volatility %, monthly cost, cost volatility %, horizon (1–36 months, clamped), runs slider (1k–100k, clamped) → real client-side Monte-Carlo: per run draws monthly revenue & cost from a Box-Muller normal around assumptions, compounds cash over the horizon, sorts endings → outputs P10/P50/P90 percentiles, % chance of negative cash, min/max range, and a colour-coded summary sentence. Spinner deferred via `setTimeout(…,30)` so the heavy loop doesn't block paint. Validates revenue > 0. _Persist: none (in-memory result)._ _Class: Simulated (genuine compute) / Indicative output._ **Interactive.**

- **Quantum-Safe Readiness** (`QuantumReadiness`, line 532) — inputs: toggle 8 fixed checklist items (`PQC_ITEMS`: crypto inventory, hybrid PQC TLS on connectors, PQC encryption at rest, lattice-signed docs, QRNG/PQC key custody, crypto-agility process, quantum-safe backups, vendor PQC attestation) → computes a live readiness score % with band (Exposed <40 / In migration 40–79 / Quantum-ready ≥80), progress bar, and N/8 steps-complete → durable post-quantum migration tracker. References NIST PQC (Kyber/Dilithium/SPHINCS+) and harvest-now-decrypt-later. _Persist: `frnt-pqc-done` (useFeatureState KV, array of done ids)._ _Class: KV (scored)._ **Interactive.**

- **Event Stream** (`EventStream`, line 588) — no inputs (derives from live `store`) → builds an activity feed from transactions (revenue inflow vs outflow, tone by sign/category), invoices (raised, tone by status), alerts (tone by severity) and obligations (scheduled, warn tone); skips invalid dates, sorts newest-first, slices top 40; renders tone-coloured event-bus rows with relative timestamps (`formatDistanceToNow`) → read-only "event-driven finance" preview feed. _Persist: none (derived)._ _Class: Indicative (derived from real store)._ **Concept-card / read-only** (interactive only as a live derived feed; no controls).

- **Tech-Readiness Radar** (`TechReadinessRadar`, line 663) — inputs: 0–5 slider per axis (`ai` / `realtime` / `tokenization` / `quantum`, each with a description) → computes overall frontier-readiness % (sum / max) and renders per-axis score/5 with segmented bars → durable self-assessment scorecard guiding roadmap (lowest axis = next investment). _Persist: `frnt-radar` (useFeatureState KV, defaults `{ai:2, realtime:2, tokenization:1, quantum:1}`)._ _Class: KV (scored)._ **Interactive.**

- **Request-to-Pay** (`RequestToPayDesigner`, line 706) — inputs: payer name/VPA, amount (₹), purpose, expiry hours → live-renders a structured `REQUEST_TO_PAY` JSON payload preview (type, payer, amount, currency INR, purpose, expiresInHours, approval: one-tap) plus a settlement-line caption when amount > 0 → preview payload only; explicitly "does not send a real payment request yet" (awaits maturing UPI Request-to-Pay rail). _Persist: none (component state only)._ _Class: Preview._ **Interactive (mockup)** — `PreviewBadge`.

- **Streaming Payroll** (`StreamingPayroll`, line 746) — inputs: monthly wage/head (₹), headcount, working hours/day → computes per-second accrual per head (wage / (22 × hours × 3600)), team accrual per working day, and team monthly outflow → illustrative continuous-payroll maths; "not wired to your payroll," needs streaming rails. _Persist: none._ _Class: Preview (Simulated maths)._ **Interactive (mockup)** — `PreviewBadge`.

- **Autonomous Treasury** (`AutonomousTreasury`, line 784) — inputs: minimum cash buffer (₹), max % of surplus to sweep, minimum yield to act (% p.a.), auto-sweep toggle, auto-draw toggle → renders a plain-language policy-preview sentence summarising the guardrails a self-driving treasury agent "would obey"; "no funds move until autonomous treasury is enabled" → durable intended-policy config. _Persist: `frnt-treasury-policy` (useFeatureState KV object)._ _Class: Preview + KV (policy persists; behaviour is concept)._ **Interactive (mockup, persisted)** — `PreviewBadge`.

- **Machine-to-Machine Pay** (`MachineToMachine`, line 821) — inputs: device name, price/unit (₹), units consumed, unit label (e.g. km/kWh) → computes total auto-settle cost (perUnit × units) and renders a programmable-money micropayment narration ("would auto-settle ₹X for N units… streaming micropayments per unit with no invoice"); "no device or CBDC rail is connected," ahead of e-rupee programmable-money support → conceptual economics calculator. _Persist: none (component state only)._ _Class: Preview._ **Interactive (mockup)** — `PreviewBadge`.

### Notes
- **Badges**: `LiveBadge` ("Live tool") marks the 6 today-tools (Alerts, Ambient, Supercompute, Quantum, Event Stream, Radar) + Overview KPIs; `PreviewBadge` marks the 4 preview tools (RTP, Streaming Payroll, Autonomous Treasury, M2M) and their shared `PreviewHeader`.
- **Genuinely buildable today** (no money rail needed): Alert Triggers, Ambient Rules (live-evaluated), Scenario Supercompute (real Monte-Carlo), Quantum-Safe Readiness, Event Stream (derived), Tech-Readiness Radar.
- **Honest previews** (rail-dependent, no live money): Request-to-Pay (UPI-RTP), Streaming Payroll (streaming-payout rails), Autonomous Treasury (autonomous agent), M2M (programmable CBDC / e-rupee).
- **Persistence** is entirely client/KV via `useFeatureState`; no dedicated backend, no real notification dispatch, no payment execution anywhere in this file.
