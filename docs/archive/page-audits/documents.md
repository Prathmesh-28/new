## Documents (`/documents`) — 23 tools

A central, tenant-scoped vault for every compliance document (GST certs, bank statements, legal, tax, payroll) plus 22 surrounding paperwork utilities — capture, sign, track expiry, validate, file and pack. Stakeholders: all (SMB owner + team), CA, ops. Backend: `/api/files` (multipart upload, list, auth-gated blob download, delete) + KV (`useFeatureState` per-tool stores).

The section selector (`docTab`) iterates a 23-entry tab array; each maps to one tool. Bullet per tool below.

- **Vault** — inputs: file upload (drag/drop or browse, `ACCEPT` whitelist, max 10 MB), name, category (gst/banking/legal/tax/payroll/other), comma tags, optional expiry date → uploads multipart to `POST /api/files`; lists via `GET /api/files` → `rowToDoc` (humanises size, derives status valid/expiring(≤30d)/expired/uploaded from `expires_at`); category-sidebar + name/tag search filter; KPIs (total docs, expiring-soon count, "encrypted in transit" badge); per-row preview (auth blob → `window.open`), download (auth blob → anchor), delete (`DELETE /api/files/:id`). → searchable document store with renewal warning banner. _Persist: backend (`/api/files` rows + stored bytes)._ _Class: **Backend** (real upload/list/download/delete, bearer-token auth)._

- **Receipt OCR Capture** (`#157`) — inputs: photo/PDF pick (`capture="environment"`), then confirmable vendor/amount/GST/date/category → `parseReceiptHints` regex over the **file name only** (largest rupee-number = total, GST/tax line, dd/mm/yyyy date, first wordy token = vendor); user verifies; `save` writes an expense record; KPIs sum count/total/GST → booked expense table. _Persist: KV `ocr-expenses`._ _Class: **Simulated** — NOT real OCR; field detection is a filename-hint heuristic, no image/PDF content read (disclaimer states "no real OCR backend", "best-effort hint only"). Flag: OCR is **preview/simulated**, not real._

- **e-Sign Workflow** (`#158`) — inputs: doc title, signer, email, method (Aadhaar e-Sign OTP / DSC / email click-to-sign) → `send` creates a doc at status `sent`; `advance` walks the manual `SIGN_FLOW` (draft→sent→viewed→signed), `decline` sets declined; KPIs (awaiting, signed, declined) → signature-tracking table. _Persist: KV `esign-docs`._ _Class: **Simulated** — statuses advanced manually by button, no ASP/eSign provider; disclaimer says "wire to NSDL/CDSL/eMudhra". Flag: e-sign is **preview/simulated**, not legally-timestamped._

- **Expiry / Renewal Vault** (`#159`) — inputs: name, type (License/Insurance/Contract/Certificate/Registration/Other), expiry date, owner/dept, alert-notice days (default 30) → computes days-to-expiry (`differenceInCalendarDays`), sorts ascending, tones each Expired/Due-soon(≤noticeDays)/Valid; banner counts expired + due-soon → renewal tracker table. _Persist: KV `expiry-items`._ _Class: **KV** (client compute; disclaimer notes alerts must be wired to Alerts page for actual WhatsApp/email)._

- **Bank Statement Parser** (`#160`) — input: pasted statement text → `parseStatement` line-by-line regex (detects date dd/mm/yyyy or ISO, narration, trailing decimal amount(s) with Cr/Dr tag or sign → debit/credit direction); KPIs (rows, total debits, total credits) → cleaned preview table. → parsed transaction rows for review (no import). _Persist: none (component `useState`, lost on tab change)._ _Class: **Preview/Indicative** — client-side regex parse only; disclaimer: "preview only, formats vary by bank"._

- **Audit Trail / Document Versioning** (`#161`) — inputs: document name, action (created/edited/viewed/shared/deleted/signed), actor, optional note → `log` records entry; version = max recorded version for that doc +1 (view/share keep version), append-prepend; filterable by document/actor → who-changed-what table with version + timestamp. _Persist: KV `audit-trail-entries`._ _Class: **KV** (append-only by convention; disclaimer: real tamper-evident logs need server-side hash chaining)._

- **Document Checklist by purpose** — inputs: pick pack (loan / new GST-reg / govt tender / vendor onboarding), tick each curated item done → progress %, 100% completion banner. _Persist: KV `doc-checklist-done` (keyed `packId::item`)._ _Class: **KV/Indicative** — curated static paperwork lists per Indian purpose; disclaimer notes lists are indicative._

- **Template Library** — inputs: pick boilerplate (vendor NOC / address-proof declaration / authorisation letter / payment-reminder), fill `{{placeholder}}` fields (date auto-inserted) → live string-replace preview, copy-to-clipboard. _Persist: none (field values in `useState`; selected template not persisted)._ _Class: **Indicative** — static boilerplate, disclaimer: "not a substitute for legal advice"._

- **Share-Link Tracker** — inputs: doc name, recipient/email, access (view/download), expiry days (default 7) → `create` generates a register row with a random `token` and `expiresAt`; `copyLink` copies an illustrative `share.headroom.app/d/<token>` URL; `revoke` flags revoked; state derived Revoked/Expired/Active; KPI of active links → share-register table. _Persist: KV `doc-share-links`._ _Class: **Simulated** — links are illustrative tokens with no server enforcement; disclaimer: "wire to a signed-URL service". Flag: share-link is **preview/simulated**._

- **KYC Collector** — inputs: counterparty name, kind (customer/vendor/employee) → per-party 7-doc checklist (PAN/Aadhaar/GST/bank-proof/address/photo/agreement) with received-toggle and progress count; "Complete" badge at full set. → onboarding KYC tracker. _Persist: KV `doc-kyc-parties`._ _Class: **KV** — collection tracker only; disclaimer: "not a verification service; validate PAN/GSTIN against registries, mask Aadhaar (DPDP)"._

- **Contract Key-Dates** — inputs: contract, kind (Renewal/Notice deadline/Payment milestone/Expiry/Review/Other), date, counterparty, note → days-to-event compute + sort, tones Passed/Soon(≤30d)/Upcoming, banner counts passed + within-30-days → urgency-sorted key-date table. _Persist: KV `doc-contract-keydates`._ _Class: **KV** (manual entry; disclaimer: verify notice-period clause wording)._

- **Bill Filing Tracker** — inputs: vendor, bill no., amount, bill date, where-filed location → `add` queues at `to-file`; `markFiled`/`unfile` toggle status with `filedAt`; To-file / Filed sub-tabs; KPIs (to-file count, pending value, filed count). → physical-filing register. _Persist: KV `doc-filing-items`._ _Class: **KV** (disclaimer: keep original tax invoice for ITC/assessment)._

- **Approval Flow** — inputs: document/request, approver, amount, raised-by, reason → `raise` creates pending request; `decide` approve/reject via `window.prompt` decision note + `decidedAt`; KPIs (pending, approved value, total) → maker-checker table. _Persist: KV `doc-approval-reqs`._ _Class: **KV** (lightweight internal trail; disclaimer: tie to authenticated user + DoA matrix for binding authorisation)._

- **GSTIN Validator / Register** — inputs: party label, 15-char GSTIN → `validateGstin`: regex layout check (2-digit state · 10-char PAN · entity digit · 'Z' · checksum) + `gstinCheckDigit` (weighted alternating 1/2, mod-36 over first 14 chars); derives state from `GST_STATE_CODES` and embedded PAN; live result banner; `save` adds pass/fail to register; KPI of valid count → checked-GSTIN register table. → offline structural + checksum validity (catches typos/fakes). _Persist: KV `doc-gstin-register`._ _Class: **Indicative** — real offline computation but **no registry call**; disclaimer: cannot confirm active status / legal-name match, verify on GST portal._

- **Document Request Tracker** — inputs: requested-from party, channel (Email/WhatsApp/Portal/In-person/Other), due-by date, multi-line/comma items list → `create` builds a request with per-item received-toggles; state Complete/Overdue(past due)/Awaiting; KPI of open requests → per-party request cards. _Persist: KV `doc-request-tracker`._ _Class: **KV** — tracker only, "doesn't send the request itself; use WhatsApp/Alerts to nudge"._

- **Naming Helper** — inputs: party/vendor, doc type (INV/RCPT/STMT/CONTRACT/GST/TDS/KYC/OTHER), doc date, amount; pattern choice (date-first / party-first / type-first) → `buildName` slugifies and joins tokens (date as YYYYMMDD, `rs<amount>`) → generated `<name>.pdf` filename, copy-to-clipboard. _Persist: KV `doc-naming-pattern` (chosen pattern only; field values are `useState`)._ _Class: **Indicative** — a convention generator, not a file renamer (disclaimer)._

- **Compliance Calendar** — inputs: filing name (e.g. GSTR-3B), category (GST/TDS/Income Tax/ROC-MCA/PF-ESI/Other), due date → per-task `docsReady` and `filed` toggles; days-to-due compute, sort filed-last then by urgency; tones Filed/Overdue/Due-soon(≤7d)/Upcoming; banner counts overdue + within-7-days → statutory-filing calendar table. _Persist: KV `doc-compliance-tasks`._ _Class: **KV** (manual due dates; disclaimer: confirm against CBIC/MCA circulars as deadlines shift)._

- **Document Bundles** — inputs: bundle title, reference/txn no.; then per-bundle add doc name + type (Invoice/Challan/Payment-proof/PO/GRN/Contract/Other) → groups linked records under one expandable bundle with per-doc remove; doc-count badge. → transaction document trail. _Persist: KV `doc-bundles`._ _Class: **KV** — links docs by name only; disclaimer: attach real vault files for a tamper-evident pack._

- **Storage Usage Summary** (`#175`) — inputs: category, file count, total size (MB) → merges into existing category line (sums count + MB); totals (storage GB/MB, files tracked); sorted bar breakdown with per-category % of total. → vault footprint breakdown. _Persist: KV `doc-storage-lines`._ _Class: **Indicative** — manually-entered figures, not live vault stats (disclaimer: "for live usage, read off the vault file list")._

- **Access Permission Matrix** (`#176`) — inputs: role/person name → `addRole` seeds a row across all 6 categories at `view`; clicking any cell cycles none→view→edit→manage; per-role remove. → intended-access policy grid. _Persist: KV `doc-access-rules`._ _Class: **KV/Indicative** — documents intent only; disclaimer: "enforce with role permissions in Settings"._

- **Watermark Note** (`#177`) — inputs: preset (CONFIDENTIAL / DRAFT / COPY / INTERNAL USE / ORIGINAL), optional doc name, optional recipient, include-issue-date toggle → composes a `·`-joined stamp string, live preview, copy-to-clipboard. → watermark/header text. _Persist: none (all `useState`)._ _Class: **Indicative/Preview** — generates text only, no real watermark applied (disclaimer: "apply as a real watermark in your PDF editor; does not encrypt")._

- **Statutory Pack** (`#178`) — inputs: pick pack (GST Registration / Annual ROC Filing / Business Loan KYC / Income Tax Return), tick collected docs → progress bar + done/total count + ready-to-submit banner at 100%. _Persist: KV `doc-statutory-collected` (keyed `packId::doc`)._ _Class: **KV/Indicative** — standard static checklists; disclaimer: requirements vary by state/entity/officer, confirm with CA._

Notes: Only **Vault** is truly backend-backed (`/api/files`). Receipt OCR, e-Sign and Share-Link tracker are explicitly **simulated/preview** (no real OCR engine, no eSign provider, no enforced signed URLs). Bank Statement Parser and Watermark Note hold no persistence (lost on tab switch). GSTIN Validator does real offline checksum math but makes no live registry call. All other tools persist to per-tool KV via `useFeatureState`.
