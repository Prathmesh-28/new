## Tokens & Programmable Money (`/tokens`) — 11 tools

Design and simulate programmable-money instruments (CBDC / tokenization) for Indian e-rupee & GIFT-City rails before they go live. Stakeholders: owner, finance. Backend: NONE — design/simulate only (no live rails). Be honest: everything here is a PREVIEW/design tool. All splits, balances, specs and lifecycle transitions compute locally in the browser; there are no live blockchain or e-rupee network calls, no funds move, and real settlement only becomes possible once CBDC/tokenization rails exist (and that integration is unbuilt).

- **Overview** — no inputs → renders an explainer card plus 10 clickable cards (each `onPick` switches to the matching tab) describing every other tool → navigation grid. _Persist: none._ _Class: Preview._
- **e-Rupee (CBDC) Ledger** — opening balance (₹), then per-movement direction (credit in / debit out), amount, note, date → manually mirrors an e-rupee wallet: sorts entries by date+id, computes a running balance from the opening figure, and totals in/out; KPIs show current balance / opening / total in / total out; rows deletable → ledger table with running balance. _Persist: live store keys `tok-erupee-opening`, `tok-erupee-entries` (useFeatureState)._ _Class: KV._
- **Programmable-Payment Rule Designer** — payee/vendor, amount (₹), trigger type (milestone / delivery / date / approval), condition ("WHEN"), optional purpose-bind → composes a plain-English "Release ₹X to vendor WHEN condition (trigger verb), usable only for purpose" sentence plus a copyable `programmable_payment_rule` JSON spec (currency `INR-eRupee`, status `draft`); saves rules to a deletable list → readable statement + JSON spec + saved-rules list. _Persist: live store key `tok-rules` (useFeatureState); JSON copied via clipboard._ _Class: KV / Indicative._
- **Smart-Contract Escrow Designer** — payer, payee, amount (₹), optional arbiter, release conditions → builds a `smart_contract_escrow` JSON draft spec (currency `INR-eRupee`); creates escrows and locally simulates the lifecycle draft → funded → released via an "advance" button (no funds move); status pill colour-coded; removable → JSON spec + escrow cards with simulated status transitions. _Persist: live store key `tok-escrows` (useFeatureState)._ _Class: Simulated / KV._
- **Tokenized-Invoice Simulator** — invoice face value (₹), number of tokens, early-funding discount (%), then per-investor name + token count → fractionalizes the invoice: computes tokens minted, per-token face value, discounted per-token price, total investor outlay; allocates tokens across investors (capped at remaining), showing each investor's share %, funds-in (at discount) and on-maturity (at face) amounts → KPI cards + investor split table. _Persist: none (component-local `useState`; investors not saved)._ _Class: Indicative._
- **Tokenized-Asset Registry** — asset name, kind (invoice / inventory / equity), face value (₹), token count → logs "tokenized" assets to a record-keeping ledger (explicitly not an on-chain mint); auto-stamps date; computes per-token value and aggregate KPIs (asset count, total face value, total tokens); rows removable → summary cards + asset table. _Persist: live store key `tok-assets` (useFeatureState)._ _Class: KV._
- **Atomic-Settlement Simulator** — Leg A party/item/value (₹), Leg B party/item/value (₹), plus a "committed" checkbox per leg → models a two-leg pay-vs-deliver (DvP) swap: warns if leg values are unequal, and shows all-or-nothing outcome — settlement "would execute atomically" only when both legs are checked, otherwise pending with which leg is missing (nothing moves) → readiness checkboxes + settlement-status panel. _Persist: none (all component-local `useState`)._ _Class: Simulated._
- **Conditional-Disbursal Builder** — total payout (₹), then per-milestone name + % of total (capped at remaining %) → splits a payout across milestones, tracking allocated vs remaining % and computing each tranche's ₹ amount; flags when 100% is allocated; rows removable → disbursal schedule table. _Persist: live store key `tok-milestones` (useFeatureState)._ _Class: KV / Indicative._
- **Token Cap-Table** — total tokens issued, then per-holder name + token count (capped at unissued, issued can't drop below held) → tracks issued / held / unissued supply and computes each holder's ownership % against issued supply; holders removable → KPI cards + holder ownership table. _Persist: live store keys `tok-captable-issued`, `tok-captable-holders` (useFeatureState)._ _Class: KV._
- **Settlement-Readiness Checklist** — toggle 8 fixed readiness items (e-rupee wallet onboarded, KYC identity, participating-bank rail, counterparties on rail, legal templates, accounting treatment, GIFT-City/IFSC setup, audit-trail/reconciliation) → tracks completion count, % and a progress bar; shows a success banner at 100% → checklist with progress. _Persist: live store key `tok-readiness` (useFeatureState, array of done ids)._ _Class: KV._
- **Glossary** — no inputs → renders 10 static plain-English explainer cards (e-Rupee/CBDC, programmable money, purpose-bound payment, smart-contract escrow, atomic settlement/DvP, tokenization, fractionalization, GIFT-City/IFSC, on-chain provenance, settlement rail) → reference cards. _Persist: none._ _Class: Preview._
