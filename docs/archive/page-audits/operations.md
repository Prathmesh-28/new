## Operations & Inventory (`/operations`) — 37 tools

Operations Hub: capture and fulfil orders, run inventory/stock-control analytics, manage procurement, and watch spend anomalies for an SMB. Stakeholders: owner, ops, finance. Backend: `/api/operations` + KV-synced (core orders/inventory/procurement flow through `AppContext` store mutators → backend + localStorage; analytics-tab records persist via `useFeatureState` into the synced `store.featureData` "app" KV namespace — written to localStorage immediately and debounce-pushed to the backend and other devices).

The tab-selector array (`Tab` type, lines 22-26; rendered list lines 161-202) has **34 entries**: overview, orders, inventory, procurement, intelligence, prices, bom, leadtime, reorder, payables, stockledger, batchtrack, jobwork, production, warehouse, stocktake, dispatch, abc, eoq, turnover, skumargin, landed, grn, scrap, returns, valuation, safetystock, carrying, aging, stockout, cyclecount, minmax, whutil, oversell. The **Overview** tab is a dashboard (not itself a working tool), and the **Inventory** tab renders three distinct tools (the SKU register plus two auto-derived analytics panels). Net total: **37 tools**, enumerated below.

### Overview / core CRUD tabs

- **Operations Overview Dashboard** (`overview`, lines 206-277) — what it does: reads live `orders`, `inventory`, `transactions` from the store → computes four KPIs (Total Order Value = sum of non-cancelled `order.totalValue`; Pending Orders count; Inventory Value = Σ qty×unitCost; Low Stock Alerts = items where qty ≤ reorderLevel) → renders KPI cards, a static WhatsApp-capture explainer card, and a "Recent Orders" preview of the latest 5. _Persist: live store (derived, read-only)._ _Class: Backend._

- **Orders Manager** (`orders`, lines 280-374) — what it does: add-order form (buyer name/phone, source whatsapp/email/phone/manual, single line item name+qty+unitPrice) → `totalValue = qty × unitPrice`, auto `orderNumber` (`ORD-<base36 ts>`), status seeded `pending` → table with per-row status workflow buttons (pending→confirmed→dispatched→delivered) and native call / WhatsApp / SMS buttons to the buyer; confirming an order triggers a revenue transaction (per toast/handler). _Persist: live store (`addOrder`/`updateOrder`/`deleteOrder`)._ _Class: Backend._

- **Inventory / SKU Register** (`inventory`, lines 377-454) — what it does: add-product form (name, SKU, qty, unitCost, reorderLevel, category from general/fmcg/pharma/electronics/apparel/food/raw_material) → table listing each SKU with stock value (qty×unitCost) and status badge (Out of stock when qty=0, Low stock when qty ≤ reorderLevel, else OK). _Persist: live store (`addInventoryItem`/`updateInventoryItem`/`deleteInventoryItem`)._ _Class: Backend._

- **Slow / Dead Stock Panel** (renders under `inventory`, lines 457-525) — what it does: maps last fulfilled-sale date per product from confirmed/dispatched/delivered orders → days since last sale → classifies each SKU (dead >180d, slow 60-180d, never-sold "unsold", else active) and sums "tied-up" value of dead+unsold → table of slow/dead/unsold SKUs with stock, value, last-sold age. _Persist: live store (derived)._ _Class: Backend._

- **Reorder Point Calculator (inventory panel)** (renders under `inventory`, lines 528-593) — what it does: avg sales per product from fulfilled orders over a ~3-month proxy window → dailyDemand = totalSold/(months×30); fixed 7-day lead time → safetyStock = ⌈dailyDemand×leadTime⌉, reorderPoint = ⌈dailyDemand×leadTime + safetyStock⌉, daysUntilOut = ⌊qty/dailyDemand⌋ → table flags items needing reorder with a one-click "Create PO →" that jumps to Procurement pre-filled (qty = max(reorderLevel×2, 20)). _Persist: live store (derived)._ _Class: Indicative._

- **Procurement / Purchase Orders** (`procurement`, lines 596-672) — what it does: low-stock "AI Procurement Suggestions" list (one-click PO pre-fill at qty = max(reorderLevel×2, 50)) + create-PO form (supplier, expected date, single item qty+unitCost) → `totalValue = qty×unitCost`, status seeded `draft` → PO cards with workflow buttons draft→approved→ordered→received. _Persist: live store (`addProcurement`/`updateProcurement`)._ _Class: Backend._

- **Anomaly Radar** (`intelligence`, lines 675-740) — what it does: runs `detectAnomalies(transactions)` (src/lib/anomalies.ts) over tenant transactions → flags duplicate payments, spend spikes, subscription creep, large new payees; buckets by severity (high/medium/low) → cards per anomaly with title, detail, date, txn count, amount, and a deep link to `/transactions`. _Persist: live store (derived from transactions)._ _Class: Backend._
