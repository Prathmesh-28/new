## Transactions & Bookkeeping (`/transactions`) — 27 tools

A unified ledger plus a Tally-grade bookkeeping suite: search/categorise/reconcile booked transactions, then layer journals, ledgers, GST/TDS, period locks, and budgeting on top. Stakeholders: finance, CA. Backend: `/api/transactions` (live `store.transactions` via `useApp` / `addTransaction` / `updateTransaction`) + KV (`featureData` namespace via `useFeatureState`, localStorage-mirrored and backend-synced) + `/api/ai/scan-receipt` (Claude vision).

Persistence legend: **Backend** = booked `store.transactions` / `updateTransaction`. **KV** = `useFeatureState` synced bag. **Indicative** = derived estimate (tax/accrual). **Simulated** = `useState` only, lost on unmount. **Preview** = computes a proposed change without writing.

Tools below cover (a) the header action buttons, (b) the primary `view === "transactions"` table view, (c) the five legacy view buttons, and (d) the 20-button "Tools" tab strip. UI filter pills/tokens (revenue/expense/payroll/loan/tax/transfer, search, date/account filters) are excluded per spec.

### Header actions & main ledger view

- **Scan Receipt** — camera/photo (`capturePhoto`) → `POST /api/ai/scan-receipt` (Claude vision extracts vendor/amount/date/category/description) → signs amount (revenue +, else −) and drops a prefilled transaction into the ledger via `addTransaction` for review; toasts on no-amount/failure. Gated by `canEdit()`. _Persist: Backend (`store.transactions`)._ _Class: Backend._
- **Export CSV** — current filtered+sorted transaction list → builds quoted CSV (Date, Description, Category, Counterparty, Amount, Account-name) → browser download. Gated by `canExport()`. _Persist: none._ _Class: Backend (read)._
- **Reconcile (modal)** — opens `ReconcileModal` (separate component) over the page. _Persist: per that component._ _Class: Backend._
- **Transactions Table** — search + category/account/date filters → sortable (date/description/amount, asc/desc) paginated table (50/page); inline per-row category edit writes via `updateTransaction`; unusual-spend flag (outflow > 2.5× that category's average abs outflow); recurring badge from `t.isRecurring`. _Persist: Backend (inline category edits)._ _Class: Backend._
- **Financial Intelligence Bar** — over all txns → 4 derived KPI cards: spend velocity (7-day vs 30-day daily-avg % change), largest expense this month, potential-duplicate count (same amount + same counterparty within 3 days), category spend spike (>20% MoM rise vs last month). _Persist: none._ _Class: Indicative._
- **Bulk Categorise / Create Rule** — floating bar on multi-select → set category on all selected via `updateTransaction`; if exactly one counterparty selected, "Create rule" saves a counterparty→category map to `localStorage` (`hr_cat_rules`) and re-categorises all matching txns. _Persist: Backend (txns) + localStorage (rule map)._ _Class: Backend._

### Legacy view buttons

- **PDC Register** — form (party, cheque no, bank, amount, due date, receive/issue) → records post-dated cheques; pending receivable/payable totals; overdue rows (due < today) highlighted; status transitions pending→cleared/bounced; CSV export. _Persist: KV (`pdc-register`)._ _Class: KV._
- **Bounce Tracker** — form (party, cheque, bank, amount, bounce date, reason, notes) → auto-sets a +30-day re-present date; tracks status open→represented→recovered→legal; totals bounced/recovered/open; NI Act §138 guidance note. _Persist: KV (`bounce-cases`)._ _Class: KV._
- **UPI Dashboard** — manual UPI entry form (VPA, name, amount, received/paid, UTR, date, note) merged with auto-detected book txns whose notes/description contain "upi"; received/paid totals, top-5 counterparties bar chart. _Persist: Simulated (manual entries `useState`); auto-detected rows are Backend-derived._ _Class: Simulated._
- **Bank Recon (Statement)** — opening balance + manually-entered statement rows (date, desc, debit, credit) → computes statement closing vs Headroom book balance (sum of all txn amounts + opening), difference, unmatched count; per-row match toggle. _Persist: Simulated (`useState` rows)._ _Class: Simulated._
- **Recurring Templates** — template form (desc, amount, income/expense, category, monthly/quarterly/annual, next date, counterparty) → monthly-equivalent (amount ÷ 1/3/12); monthly recurring income/expense/net KPIs; projects upcoming occurrences over next 90 days (guarded loop); active/paused toggle. Planning only — not booked to ledger. _Persist: KV (`recurring-templates`)._ _Class: KV (occurrences = Indicative)._

### Tools tab strip (20)

- **Auto-Categorise (Rules Engine)** — build rules (field payee/description, op contains/equals, text, min/max ₹ on abs amount, target category) → first-match-wins evaluation over the ledger; shows which txns *would* re-classify (capped 100). Does not write — apply happens on the main table / Bulk Tag. _Persist: KV (`txn-cat-rules`) for the rules._ _Class: Preview._
- **Recon Workbench** — manually-added bank lines (date, signed amount, narration) → auto-matches one book txn per line by same amount (±0.5) within ±3 days; counts matched/unmatched(bank)/book-without-line; manual clear/reopen of unmatched lines; lists book txns with no bank line (deposits-in-transit / outstanding cheques). _Persist: Simulated (lines & cleared set `useState`)._ _Class: Simulated (matching is Backend-derived)._
- **Split Txn** — pick a booked txn → allocate its absolute amount across N legs (category, memo, amount); "split equally" helper; live allocated/remaining balance check. Computation/preview only; does not post the split. _Persist: Simulated (legs `useState`)._ _Class: Preview._
- **Bulk Tag** — filter ledger by search + from-category → multi-select rows (cap 300 shown) → re-categorise all selected to a target category via `updateTransaction`. _Persist: Backend (`store.transactions`)._ _Class: Backend._
- **Transfer Detect** — finds offsetting debit/credit pairs (same magnitude, opposite sign, ±2 days, *different* bank accounts) → "Tag (all) as transfer" sets both legs' category to `transfer` via `updateTransaction` so self-transfers aren't double-counted in revenue/spend; shows gross value moved and already-tagged count. _Persist: Backend (txn category writes)._ _Class: Backend (detection = Indicative)._
- **Cost Centers** — create projects/cost-centres; assign each txn to a project (txnId→projectId map) → per-project P&L = assigned inflows (revenue) − assigned outflows (cost) → net. _Persist: KV (`txn-cost-centers` list + `txn-cost-center-map` assignments)._ _Class: KV._
- **Cash / Accrual** — basis toggle (cash | accrual) + window (3/6/12M) → cash basis = revenue received & expenses paid in window; accrual adds unpaid invoiced revenue (`store.invoices` where status≠paid) as a revenue adjustment; expense-side accrual not modelled. P&L statement (cash vs accrual columns). _Persist: none (UI state only)._ _Class: Indicative._
- **Journal Entry** — double-entry voucher composer: legs (account, debit | credit, mutually exclusive), narration, date → enforces balanced (Dr=Cr, non-zero) and every leg named → posts a durable JV record (auto voucher no `JV-####`); does NOT touch the cash/bank ledger. _Persist: KV (`txn-manual-journals`)._ _Class: KV._
- **Trial Balance** — re-foots live over all booked txns: each category's net lands as a debit (net outflow) or credit (net inflow), plus a "Cash & Bank (control)" account absorbing total net movement so columns tie out; shows total Dr/Cr and balanced flag. Single-entry-derived. _Persist: none._ _Class: Indicative._
- **Day Book** — pick a day (date picker + prev/next arrows) → opening balance (sum of all txns before the day), that day's receipts/payments ordered by id with a running balance, closing balance. _Persist: none._ _Class: Backend (read/derived)._
- **Party Ledger** — pick a counterparty → chronological statement of account (debit = outflows, credit = inflows) with running balance; total received/paid/net. For ledger confirmations. _Persist: none._ _Class: Backend (read/derived)._
- **Opening Balance** — per-bank-account opening balance entry + "as-of" date → current balance = opening + movement (sum of txns dated on/after as-of); totals across accounts. For Tally migration. _Persist: KV (`txn-opening-balances` + `txn-opening-asof`)._ _Class: KV._
- **Write-Off** — record bad-debt / short-receipt / discount / rounding / other write-offs (date, party w/ datalist of counterparties, amount, reason, notes) → total written off, bad-debt subtotal, by-reason breakdown. Register only — not posted to ledger. _Persist: KV (`txn-write-offs`)._ _Class: KV._
- **Period Lock** — set a "locked up to (inclusive)" date → flags txns on/before it as locked (correct via reversing journal, not edit) vs open; counts/value locked vs open entries; soft lock only (no enforcement), framed against MCA audit-trail expectation. _Persist: KV (`txn-period-lock-upto`)._ _Class: KV._
- **Chart of Accounts** — maintain CoA grouped under 5 heads (asset/liability/equity/income/expense), seeded from txn categories (codes 1000–5100); add/remove accounts; live usage (txn count + abs value) mapped from categories onto account names. _Persist: KV (`txn-chart-of-accounts`)._ _Class: KV._
- **GST Ledger** — month + slab (5/12/18/28%) → back-computes tax embedded in revenue (output GST) and expense (input GST/ITC) lines treating amounts as tax-inclusive (factor = rate/(100+rate)) → net GST payable or ITC carry-forward. GSTR-3B-style estimate. _Persist: KV (`txn-gst-ledger-rate`)._ _Class: Indicative._
- **TDS Ledger** — section (194C/J/H/I/Q with preset rates) + threshold ₹ → per-counterparty gross of expense+payroll outflows; where gross ≥ threshold, estimated TDS = gross × rate; parties-above-threshold count, total estimated TDS, gross deductible spend. _Persist: KV (`txn-tds-ledger-section` + `txn-tds-ledger-threshold`)._ _Class: Indicative._
- **Cash / Bank Split** — classifies each txn's account as cash-type (name/provider contains "cash"/"petty"/"wallet", or no account) vs bank → cash vs bank net (in − out) cards, total net, cash share of outflow %. _Persist: none._ _Class: Backend (read/derived)._
- **Counterparty 360** — per-counterparty profile built live from txns: received (in), paid (out), net, txn count, last-seen date; sortable by most-paid / most-received / net exposure / activity. _Persist: none._ _Class: Backend (read/derived)._
- **Budget vs Actual** — per spend category (expense/payroll/tax/loan) monthly budget entry + month picker → actual outflow for month, utilisation % bar (amber >80%, red on overrun), per-row over-budget delta; total budget/actual/remaining-or-over. _Persist: KV (`txn-budget-actual`)._ _Class: KV._
