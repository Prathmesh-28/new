# Data & Import (`/data`) — 20 tools

Bring SMB financials into Headroom fast (CSV/Tally/statement import), keep them clean (quality, dedupe, find-replace), and get them back out (backups, range/archive exports, format converters). Stakeholders: CA, finance, owner. Backend: client-only — live Zustand store (`useApp`) for transactions/invoices/accounts/loans, browser KV via `useFeatureState` for tool presets/logs, and Blob/`download*` for all exports. No server round-trips for any tool here.

Tabs (from the selector array, line 88): `overview`, `tally`, `mapper`, `consolidate`, `backup`, `quality`, `dedupe`, `replace`, `templates-store`, `filings`, `archive`, `profiler`, `csv-json`, `number-clean`, `gstin-check`, `pivot`, `statement-parse`, `range-export`, `paste-dupes`, `json-fmt`.

- **Overview** — renders the page header + 4 stat cards (transactions / invoices / bank accounts / active loans counts from live store) and 4 action cards: (1) **Bulk import transactions** opens `TransactionImportModal` (auto-detects date/amount/description, guesses categories, preview-then-commit) and prepends rows to live store, creating a `manual-import` account if none exists; (2) **Load sample data** runs `generateDemoData()` to replace firm/accounts/transactions/invoices/loans/obligations with FY23–FY28 demo set (confirm-gated); (3) **Clear all** wipes transactions/invoices/accounts/loans/obligations (confirm-gated); (4) **CSV templates** download static transactions/invoices template CSVs. All gated on `canEdit()`. _Persist: live store (import/demo/clear write transactions, invoices, bankAccounts, activeLoans, obligations); templates are static download._ _Class: Backend (live store mutation) + Preview (modal)._

- **Tally Bridge** (`TallyBridge`, #162) — Export: live `store.transactions` → generated Tally `<ENVELOPE>`/`IMPORTDATA` voucher XML (Receipt/Payment vouchers, party + "Bank Account" ledger double-entry, dates de-hyphenated, XML-escaped) downloaded as `.xml`. Import: pasted Tally voucher XML → `DOMParser` extracts DATE/NARRATION/VOUCHERTYPENAME + first non-bank/cash ledger AMOUNT, signs by voucher type (payment/purchase negative, receipt/sales positive, else raw sign), categorises revenue/expense → preview table (first 50) → commit prepends to live store. _Persist: live store on import; download on export._ _Class: Backend._ **Real bidirectional Tally import/export** (client-side XML generate + parse), not just a format template — though it warns to verify ledger mapping in Tally after import.

- **CSV Mapper** (`CsvMapper`, #163) — Paste arbitrary CSV → `splitCsvLine` parse → user maps each column to date/amount/description/counterparty/ignore via dropdowns; options for header row and "treat all amounts as expenses (negate)". Amount column required; builds Transaction rows (`toIsoDate` dates, numeric-cleaned amounts, revenue/expense by sign) → preview (first 50) → commit prepends to live store under `importAccountId`. _Persist: live store on commit._ _Class: Backend._ Real CSV mapper/importer.

- **Consolidation** (`MultiEntityConsolidation`, #164) — Maintain a list of group entities (name, ownership %, revenue/expense/cash); "Add this firm from live data" derives revenue/expense from live transaction signs and cash from bank balances. Computes gross totals, applies a single inter-company elimination figure to both revenue and expense, derives Group PBT, minority interest (Σ entity PBT × (1−ownership%)) and owners' profit. _Persist: KV `data-consolidation-entities` (entity list); elimination input is component state only._ _Class: KV + Indicative (AS-21-style; self-described as indicative, intra-group balances/unrealised profit not auto-detected, "verify with your CA")._

- **Backup & Export** (`ScheduledBackup`, #165) — One-click **Full backup (JSON)** = snapshot of firm + accounts + transactions + invoices + loans + obligations + featureData → download; **Transactions (CSV)** = escaped transactions CSV → download. Each run appends to a durable export log (capped 30). Cadence selector (off/daily/weekly/monthly) computes a due/overdue/up-to-date reminder from last log entry. _Persist: KV `data-backup-cadence` + `data-backup-log`; actual data export is download-only._ _Class: KV + Backend (reads live store) — but note the cadence is a reminder only, exports are manual (no real scheduling/server upload)._

- **Data Quality** (`DataQualityChecker`, #166) — Read-only scan of live transactions: counts missing description, missing counterparty, invalid/blank date, zero amount, future-dated, no bank account, and likely duplicates (date+amount+counterparty signature); derives a health score (100 − issues/total ×100) and clean-row count. Per-check table with OK/Review status. _Persist: none (memoised over `store.transactions`)._ _Class: Backend (reads live store, computed)._

- **Dedupe** (`TransactionDedupe`, #167) — Groups live transactions by date+amount+counterparty+description; reports duplicate group count and removable row count; "Remove" (confirm-gated) keeps first occurrence of each signature and rewrites `store.transactions`. Preview table of first 50 groups with copy counts. _Persist: live store on dedupe._ _Class: Backend._

- **Find & Replace** (`BulkFindReplace`, #168) — Pick field (counterparty/description), enter find/replace, optional whole-value match; case-insensitive substring (or whole) match against live transactions, live match count + preview (first 50), apply (confirm-gated) rewrites the field across matching rows via escaped regex `replace`. _Persist: live store on apply._ _Class: Backend._

- **Mapping Templates** (`MappingTemplateStore`, #169) — Save named column-order presets (name + comma-separated column string + timestamp); list/delete; "Export all (JSON)" downloads the preset list. Storage of reusable layouts (e.g. "HDFC current account"); note: presets are not auto-applied by the CSV Mapper — they're a manual reference store. _Persist: KV `data-mapping-templates`; export is download._ _Class: KV._

- **Filing Templates** (`FilingTemplates`, #170) — Four static, hardcoded CSV templates for Indian filings/bulk-loads: GSTR-1 B2B outward supplies, opening balances, fixed-asset register, vendor/counterparty master. Each downloads a correctly-headed sample CSV. _Persist: none (static download)._ _Class: Indicative (format templates only; self-described "confirm exact column requirements with the GST portal")._

- **Archive & Purge** (`ArchivePurge`, #171) — Choose a cut-off date; counts/values transactions older vs kept; "Download archive CSV" exports older rows (escaped CSV); "Purge" (confirm-gated, edit-only) removes pre-cutoff rows from `store.transactions`. _Persist: live store on purge; archive is download._ _Class: Backend._

- **Column Profiler** (`ColumnProfiler`, #172) — Paste any CSV → per-column fill rate, distinct count, type (numeric if ≥80% of filled cells parse as numbers, stripping ₹/commas), and for numeric columns count/sum/mean/median/min/max. Read-only, browser-only. _Persist: none (component state + memo)._ _Class: Indicative (pasted-data analysis, no store)._

- **CSV ↔ JSON** (`CsvJsonConverter`, #173) — Two-way converter: CSV → JSON array of objects (header-keyed), or JSON array of objects → flattened CSV (union of keys, nested values JSON-stringified). Error messages for malformed input; output textarea + download. _Persist: none._ _Class: Indicative (pure in-browser format conversion of pasted data)._

- **Number Cleanup** (`NumberCleanup`, #174) — Paste a column of messy amounts; per-line parser handles ₹/$ symbols, thousands separators, bracket negatives, trailing CR/DR direction, and k/lakh/lac/crore suffix multipliers → signed numbers. Stat cards (parsed/unparseable/total/rows), per-row OK/Skipped table (first 100), download cleaned `original,cleaned` CSV. _Persist: none._ _Class: Indicative (pasted-data transform)._

- **GSTIN Validator** (`GstinValidator`, #175) — Paste GSTINs (one per line); validates 15-char structure via regex, state code against an embedded `GST_STATES` map, embedded PAN segment, and the official mod-36 checksum digit (`gstinChecksum`). Valid/invalid/checked counts, per-row status+state+reason table (first 100), download report CSV. Offline — no portal call. _Persist: none._ _Class: Indicative (structural + checksum only; self-described "does not confirm the GSTIN is active/registered")._

- **Pivot Builder** (`PivotBuilder`, #176) — Paste CSV with header → pick group-by column + numeric value column → grouped sum/count/average per group, sorted by |sum|, with grand total; downloadable pivot CSV. _Persist: none._ _Class: Indicative (pasted-data analysis)._

- **Statement Parser** (`StatementParser`, #178) — Paste raw bank-statement text (one row per line, leading date required); heuristically sniffs per line: `toIsoDate` date, all money-looking numbers, Dr/Cr keyword direction, picks largest-magnitude amount (drops trailing running balance when ≥3 numbers), strips numbers/keywords for description/counterparty. Credit/debit totals + preview (first 50) → commit prepends Transactions to live store under `importAccountId`. _Persist: live store on commit._ _Class: Backend (import) — but a heuristic parser, self-flagged "verify amounts and Dr/Cr direction before importing."_

- **Date-Range Export** (`DateRangeExport`, #179) — From/to date window filters live transactions (inclusive, end-of-day); shows matched rows + net amount; exports the subset as escaped CSV. _Persist: none (reads live store; export is download)._ _Class: Backend (reads live store)._

- **Paste Dedupe** (`PasteDuplicateFinder`, #180) — Paste any list (one value/line, e.g. invoice numbers, GSTINs, emails); counts repeats (optional case-sensitivity), shows total/unique/duplicated stats + duplicates-with-counts table (first 100), exports de-duplicated unique list as CSV. _Persist: none._ _Class: Indicative (pasted-data analysis)._

- **JSON Formatter** (`JsonFormatter`, #181) — Paste JSON → validate, pretty-print (2-space) or minify; error message on invalid JSON; copy to clipboard or download result. _Persist: none._ _Class: Indicative (pure in-browser format utility)._

## Notes
- Excluded UI filter/mode tokens (not standalone tools): `amount`/`daily`/`weekly`/`monthly` cadence selectors, `json2csv`/`csv2json` and `pretty`/`minify` mode toggles, map-field options, etc.
- Backend-class tools all mutate or read the **live Zustand store** (transactions etc.); there is no server/Django call from this page — "Backend" here means live app state, not a remote API.
- Tally Bridge and Statement Parser are the only two heuristic/lossy importers flagged for post-import verification; CSV Mapper is deterministic (user-driven column mapping).
