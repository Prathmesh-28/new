## Automation & Workflows (`/automation`) — 31 tools

No-code finance-ops fabric: define IF-THEN rules, schedulers, approval chains, validation checks, and watchers, all previewed against live transactions/invoices/obligations/bank balances. Stakeholders: owner, finance, ops. Backend: KV-synced via `useFeatureState` (per-tool keys on the synced account). NOTE: no live cron — every rule/schedule/trigger evaluates on-demand against current store data when the tab renders or a Preview/Scan button is clicked; nothing fires, sends, posts, or mutates server-side. Header copy states this explicitly. UI filter tokens (rule action picker, bulk-action picker, notification-event lists) are excluded below.

- **Overview** — reads counts from all KV stores (active rules, reminders, chains, tasks, webhooks, logged events) → six clickable stat cards + three "where to start" jump links. _Persist: reads `auto-rules`/`auto-reminders`/`auto-approval-chains`/`auto-tasks`/`auto-webhooks`/`auto-activity`._ _Class: KV (read-only dashboard)._
- **Rule Builder** — name + subject (transaction|invoice) + field + op (>,<,==,contains) + value + action (flag/notify/tag/escalate) → IF-THEN rule builder; Preview evaluates condition against live `store.transactions`/`store.invoices` and lists matching rows (count + first 25); enable/pause toggle → stored rule + match preview. _Persist: `auto-rules`._ _Class: Preview (action never executed)._
- **Reminder Scheduler** — anchor (invoice due / obligation due / manual date) + record/label + day offset + channel (whatsapp/email/in-app) → scheduler; computes fire date = baseDate + offset, sorts, shows status (past/today/in Nd) → reminder rows table. _Persist: `auto-reminders`._ _Class: Simulated (delivery is client-side preview, no send)._
- **Approval Chains** — chain name + spend threshold + ordered approver steps each with mode (any one / all) → approval-chain builder; preview counts current outflows (negative txns) ≥ threshold that would route through → stored chain + routed-count. _Persist: `auto-approval-chains`._ _Class: Preview (routing illustrative, no sign-off engine)._
- **Trigger Library** — pick from 6 hardcoded recipes (overdue nudge, large payout, big invoice, payroll, tax, unpaid invoices) → one-click install seeds a ready-made `RuleRow` into Rule Builder. _Persist: writes `auto-rules`._ _Class: KV (recipe templates → seeds a rule)._
- **Bulk Runner** — selection (overdue-invoices / pending-invoices / flagged-txns) + action (send-reminder / mark-followup / tag) → batch picker; lists live matching records, "Preview run" logs intended action across N records. _Persist: none (logs to `auto-activity`)._ _Class: Simulated (dry-run, mutates/sends nothing)._
- **Notification Rules** — event (from fixed list) + channel (whatsapp/email/in-app) + recipient + quiet-hours toggle (daily digest vs instant) → notification routing registry table. _Persist: `auto-notifications`._ _Class: Simulated (definitions only; delivery depends on unconnected channels)._
- **Recurring Tasks** — task title + cadence (daily/weekly/monthly/quarterly) + anchor date + owner → scheduler; computes next occurrence ≥ today (cadence step days) → tasks table with next-run. _Persist: `auto-tasks`._ _Class: Indicative (next-run computed; nothing fires without cron)._
- **Activity Log** — passive consumer of the shared event stream every tool appends to (create/run/delete, capped at 200) → chronological audit feed; Clear-log button. _Persist: `auto-activity` (live shared store)._ _Class: KV (local audit trail, not backend execution log)._
- **Webhook Registry** — name + endpoint URL (http/https validated) + event → outbound webhook registry table with active/disabled toggle. _Persist: `auto-webhooks`._ _Class: Simulated (config only; no dispatcher, no secrets/signing collected)._
- **Templates Gallery** — 6 end-to-end blueprints (dunning, month-end close, P2P gate, vendor onboarding, idle-cash watch, GST pipeline) with persona + numbered steps → "Use template" seeds a starter rule (if `rule` present) or treats as manual checklist. _Persist: writes `auto-rules` (logs to `auto-activity`)._ _Class: KV (template→rule seed / checklist; multi-step execution needs absent orchestrator)._
- **Numbering Rules** — prefix + pad width + start + reset-yearly toggle → invoice numbering-rule builder; sample = prefix + optional FY tag + (start + current invoice count) zero-padded → scheme rows with computed next number. _Persist: `auto-numbering`._ _Class: Preview (sample computed from invoice count; assignment happens elsewhere)._
- **Auto-Categorize** — keyword + target category (revenue/expense/payroll/loan/tax/transfer) → auto-categorize rule; previews live txns whose description/counterparty contains keyword and how many would re-class (category differs). _Persist: `auto-categorize`._ _Class: Preview (no data mutated)._
- **Escalation Matrix** — day-overdue threshold + assignee → escalation tiers (sorted); buckets live overdue invoices into the highest tier each exceeds, shows count + ₹ per tier. _Persist: `auto-escalation`._ _Class: Preview (assignment illustrative, no one paged)._
- **SLA Timers** — stage (from fixed list) + window in hours + on-breach action (escalate/remind/reassign) → SLA-policy table (hours formatted h/d). _Persist: `auto-sla`._ _Class: Indicative (policy stored; no live clock server-side)._
- **Recurring Journals** — template name + debit acct + credit acct + amount + cadence (monthly/quarterly) + first-post date → recurring-journal templates; computes next-post date → table with Dr→Cr entry. _Persist: `auto-journals`._ _Class: Indicative (next-post computed; nothing posted to ledger)._
- **Document Routing** — keyword + destination folder + (optional) ledger → routing rules; estimates match count from live txns whose description/counterparty contains keyword. _Persist: `auto-routing`._ _Class: Preview (match estimate; no files moved)._
- **Data Validation** — toggle any of 5 integrity checks (missing invoice number, future-dated invoice, large transfer-category outflow >₹50k, duplicate amount+customer, revenue posted as outflow); each runs live against store and lists findings; "Run enabled checks" tallies total issues → per-check finding lists. _Persist: `auto-validation` (enabled-check ids; logs runs to `auto-activity`)._ _Class: Preview (findings surfaced, nothing auto-corrected)._
- **Scheduled Reports** — report (from fixed list) + cadence (daily/weekly/monthly) + channel (email/whatsapp) + recipient + first-delivery date → report-schedule jobs; computes next delivery → table. _Persist: `auto-reports`._ _Class: Simulated (next-delivery computed; no compilation/send without backend)._
- **Discount Rules** — min invoice value + discount % + optional label → tiered discount rules (sorted); preview applies each invoice's best-matching tier across live AR, shows qualifying count + est. total discount. _Persist: `auto-discounts`._ _Class: Preview (illustrative figures, not applied to invoices)._
- **Reminder Cadences** — cadence name + multi-step builder (offset days from due + channel whatsapp/email/call + note) → dunning-cadence templates; illustrates each step's fire date against the nearest-due open invoice. _Persist: `auto-cadences`._ _Class: Simulated (preview against sample invoice; sending needs backend)._
- **Segment Builder** — name + subject (transaction|invoice) + match logic (ALL/ANY) + multi-condition builder (field + op + value) → saved reusable segment; Preview evaluates AND/OR conditions against live records (count + first 25). _Persist: `auto-segments`._ _Class: Preview (counts computed; meant to later feed bulk actions/policies)._
- **KPI Watch** — metric (cash-balance / overdue-AR / open-AR / obligations-due≤30d / month-outflow) + op (below/above) + threshold + notify-target → KPI watch rules; computes current metric value live and flags breach state now. _Persist: `auto-kpiwatch`._ _Class: Preview (breach flagged; no alert sent)._
- **Tier Reminder Policy** — tier (platinum/gold/standard) + min outstanding floor + first-nudge offset days + channel → one policy per tier (replaces same tier); classifies live customers by total open outstanding into matching tier with nudge/channel. _Persist: `auto-tier-policy`._ _Class: Preview (classification table; sending needs backend)._
- **Status-Update Rules** — days-past-due threshold → auto-flip rule (pending → overdue, only-from pending); lists exactly which pending invoices would flip; "Preview run" logs the dry-run. _Persist: `auto-status-rules` (logs runs to `auto-activity`)._ _Class: Simulated (dry-run; mutates nothing)._
- **Run History** — derived view filtering `auto-activity` to kind=="run" only; aggregates run count + last-run timestamp per tool → per-tool stat cards + run feed. _Persist: reads `auto-activity`._ _Class: KV (local execution history; no scheduled executor)._
- **Credit-Limit Rules** — scope (all customers / one customer) + customer + credit limit + on-breach (flag/block) → credit-limit rules; lists customers whose live unpaid outstanding already exceeds the limit (count + offenders). _Persist: `auto-credit-limit`._ _Class: Preview (risk surfaced; nothing auto-blocked)._
- **Payment Matching** — amount tolerance % + match window days → reconciliation rule; finds candidate matches between open invoices and revenue inflows within tolerance band and date window (gap ≥0, ≤window). _Persist: `auto-paymatch`._ _Class: Preview (likely matches listed; nothing marked paid)._
- **Low-Balance Trigger** — watch scope (combined total or a specific bank account) + floor ₹ → cash-floor trigger; evaluates live balances now, shows breach/healthy state. _Persist: `auto-lowbalance`._ _Class: Preview (breach state shown; cannot push alert without backend watcher)._
- **Recurring Invoices** — customer + amount + cadence (weekly/monthly/quarterly) + first-invoice date → billing-template rules; previews next six raise dates + annualised value. _Persist: `auto-recurringinv`._ _Class: Indicative (schedule previewed; no invoices created, no scheduler)._
- **Duplicate-Payment Check** — day window between payments → read-only scan grouping outflows to same counterparty with identical amount within window; shows payment dates + ₹ at risk; "Scan" logs the run. _Persist: `auto-dupcheck` (stores window int; logs runs to `auto-activity`)._ _Class: Preview (read-only scan; reverses/blocks nothing)._
