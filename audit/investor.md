## Investor Relations (`/investor`) — 14 tools

A role-gated investor portal that bundles AA-style portfolio monitoring, live deal flow, syndicates, and a suite of fundraise/IR planning tools — most metrics computed live from the firm's transactions, the deal/portfolio data illustrative. Stakeholders: owner, investor. Backend: `/api/capital/raises/*` (public list + commit) + AppContext capital store + `useFeatureState` KV. NOTE: this page is role-gated (`investor`/`super_admin`, else redirects to `/dashboard`) and leads with a portfolio-monitoring view.

Tabs (`TABS` array, 14 entries): `portfolio`, `dealflow`, `syndicates`, `update-composer`, `data-room`, `tearsheet`, `exit-waterfall`, `mrr-movement`, `burn-efficiency`, `cohort-retention`, `fundraise-pipeline`, `board-agenda`, `runway-timing`, `esop-pool`.

- **Portfolio Monitoring** (`PortfolioTab`) — fixed `MOCK_PORTFOLIO` of 4 companies (invested, equity %, runway days, monthly burn/revenue, burn/revenue trend, AA-verified flag, last alert) → derives totals (total deployed, company count, avg runway, active-alert count) and splits into "Early Warning / Needs Attention" (runway < 60d OR alert severity critical/high) vs "On Track"; each `CompanyCard` color-codes runway/severity and renders trend arrows; AA "sample preview" trust banner up top → at-risk + healthy company cards with metrics. The critical-alert count feeds the Portfolio tab badge. _Persist: none (in-memory mock constant)._ _Class: Simulated._

- **Deal Flow** (`DealFlowTab`) — live `GET /api/capital/raises/public` raises (name, raise_type/track, target/raised amount, status, closes_at) + search box, track filter (all/rev_share/reg_cf/reg_a_plus), sector/rev-band filter tokens (declared but rev/sector filters not wired to filtering) → filters by name+track, then `enriched` decorates each with deterministic mock metadata (sector, "verified" revenue, MoM growth %, DSO, employee count, founded year, use-of-funds via index math); per-card computes funded % and days-left, flags raises the user already invested in (`capitalInvestments` match on raiseId+email) → raise cards with sample MRR/growth/use-of-funds, funding progress bar, and "Express Interest →" button (opens commit modal); track-explainer footer (rev_share/reg_cf/reg_a+). _Persist: live API for raise list; commit writes via AppContext (see Express Interest modal)._ _Class: Backend (raise list + commit) with Simulated per-raise metrics._

- **Express Interest modal** (in `InvestorPage`, triggered from Deal Flow) — selected raise + investment amount input + "not binding / KYC required" agreement checkbox → on confirm `POST /api/capital/raises/:id/commit { amount }`, uses returned `equity_pct` (fallback amount÷target×100), calls `addCapitalInvestment` (status `confirmed`), toasts, reloads raises; live estimated-ownership % preview shown as amount is typed. _Persist: Backend POST + AppContext capital store (`addCapitalInvestment`)._ _Class: Backend._

- **Syndicates** (`SyndicatesTab`) — seeded `MOCK_SYNDICATES` (2) plus create-form (name + min check size) → "Create Syndicate" prepends a new local syndicate (random UUID, lead = user email prefix, target 5M, 45-day close); "Join Syndicate" adds id to a local `joined` Set and toasts a KYC-handoff message; each card shows committed-vs-target % bar, members, min check, days-to-close. _Persist: none (component `useState`; resets on unmount/reload)._ _Class: Simulated._

- **Investor Update** (`InvestorUpdateComposer`) — live transactions → derives current-month MRR (revenue txns), monthly burn (expense+payroll), cash (sum of all amounts), net burn (burn−MRR floored at 0), runway months (cash÷net burn, ∞ if none) + free-text Highlights and Asks inputs → assembles a formatted monthly investor-update email draft (subject, headline metrics, highlights, asks, sign-off from email prefix); Copy-to-clipboard and `mailto:` email buttons. _Persist: none (draft is derived/`useMemo`; highlights/asks are local `useState`)._ _Class: Backend-derived live metrics (Indicative draft)._

- **Data Room** (`DataRoomBuilder`) — 16-item `DATA_ROOM_TEMPLATE` across categories (Corporate, Cap Table, Financials, Tax, Legal, HR) → each item's status cycles missing → in_progress → ready on click; computes ready count and readiness % progress bar; grouped by category; Reset restores all to "missing". _Persist: `useFeatureState("investor-data-room")` (cross-device KV)._ _Class: KV._

- **KPI Tearsheet** (`KpiTearsheet`) — live transactions → computes current-month MRR, ARR (MRR×12), prior-month MRR for MoM growth %, monthly burn (expense+payroll), cash, net burn, runway months, gross margin ((MRR−burn)/MRR) → 8-cell one-pager grid (MRR, ARR, MoM growth, burn, net burn, cash, runway, gross margin) color-coded; dated header with firm name. _Persist: none (derived from live transactions)._ _Class: Backend-derived live metrics (Indicative)._

- **Exit Waterfall** (`ExitWaterfall`) — editable share-class table (name, type pref/common, invested, shares, pref multiple; default 4 rows) + exit-value input → models non-participating preferred payout: if exit ≤ total liquidation preference, prefs share pro-rata; else iteratively decides per pref class whether to take preference or convert to common (as-converted vs preference), then distributes residual to common+converting on a share basis; shows per-class treatment, payout, % of exit, and total distributed; add/remove rows. Disclaimer: simplified (single pref, no participation cap/dividends), indicative only. _Persist: `useFeatureState("investor-exit-waterfall")` (cross-device KV)._ _Class: KV + Indicative (cap-table waterfall model)._

- **MRR Movement** (`MrrMovement`, uses `useMonthlySeries(12)`) — 12-month revenue/expense series from live transactions → current vs prior month MRR → net-new MRR, decomposed into expansion (positive delta) vs contraction/churn (negative delta), ARR (MRR×12), MoM growth %, net revenue retention (MRR/prevMRR ×100) → metric cards + a 12-month recurring-revenue bar chart. Footnote: delta-based proxy until line-item subscription data exists. _Persist: none (derived from live transactions)._ _Class: Backend-derived live metrics (Indicative)._

- **Burn Efficiency** (`BurnEfficiency`, uses `useMonthlySeries(6)`) — last-two-months MRR + current burn → net-new ARR ((MRR−prevMRR)×12), net burn, burn multiple (net burn ÷ net-new MRR; null if no net burn), SaaS magic number (net-new ARR ÷ annualized spend), gross margin → headline burn-multiple tile with Bessemer-style rating band (Elite/Great/Good/Suspect/Concerning) plus supporting metric cards and a static benchmark legend. _Persist: none (derived from live transactions)._ _Class: Backend-derived live metrics (Indicative)._

- **Cohort Retention** (`CohortRetention`, uses `useMonthlySeries(12)`) — months with revenue → builds a retention triangle: each starting month is a cohort, each subsequent month indexed to 100 at the cohort's first month (revenue/base ×100); heatmap-colored cells by retention band (≥110 green … <60 red); empty state when no revenue. Footnote: proxy from monthly totals, not true per-customer cohorts. _Persist: none (derived from live transactions)._ _Class: Backend-derived live metrics (Indicative)._

- **Raise Pipeline** (`FundraisePipeline`) — investor CRM rows (name, firm, stage, check size, next step; 3 seeded) → add investor (defaults to "sourced"), per-row stage select across STAGE_ORDER (sourced→intro→pitched→diligence→term_sheet→closed→passed), advance-stage button (caps at "closed"), editable next-step field, remove; summary cards: closed/committed (sum of closed checks), in-play (sum excluding closed/passed), active-conversation count (excluding passed). _Persist: `useFeatureState("ir-fundraise-pipeline")` (cross-device KV)._ _Class: KV._

- **Board Agenda** (`BoardAgenda`) — meeting date + agenda items (topic, minutes, owner, done; 5 seeded) + free-text minutes + action items (task, owner, due, done; 1 seeded) → add/toggle/remove agenda topics (total-minutes sum shown), capture minutes, add/toggle/remove action items (open-action count shown). _Persist: `useFeatureState` keys `ir-board-meeting-date`, `ir-board-agenda`, `ir-board-minutes`, `ir-board-actions` (cross-device KV)._ _Class: KV._

- **Next-Raise Timing** (`RunwayTiming`) — cash + net monthly burn pre-filled from live transactions, plus editable burn-growth %/mo and raise lead-time months → simulates month-by-month cash drawdown with compounding burn growth (120-month cap) to get runway months and cash-zero date; start-raise = runway − lead time, flagged "urgent" if ≤ 1 month (red banner) → runway / start-raising-in / lead-time-buffer tiles with projected dates. _Persist: none (seeded from live transactions; assumptions in local `useState`)._ _Class: Backend-seeded live metrics + Simulated drawdown projection._

- **ESOP Pool** (`EsopPool`) — pool size + grant register (grantee, options, 48mo vest / 12mo cliff defaults, grant date; 3 seeded) → granted total, available (pool−granted), allocation % bar; per-grant vested-to-date via linear monthly vest after cliff (days-since-grant ÷ 30.44 vs cliff/vest); update pool (rejects below already-granted), add grant (rejects over available), remove grant. _Persist: `useFeatureState` keys `ir-esop-pool-size`, `ir-esop-grants` (cross-device KV)._ _Class: KV + Indicative (vesting schedule)._
